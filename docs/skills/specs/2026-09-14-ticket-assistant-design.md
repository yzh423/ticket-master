# 候票台首版设计

用户批准的目标是固定场次、人数和总预算，在可接受的多个票档之间做选择，并跟踪官方销售机会。Windows 本地 Electron 应用以 React 展示任务，SQLite 保存在本机。每个任务包含活动规则、带来源的销售机会、准备检查、排序的票档和人工确认的结果。后端只暴露有限的 IPC 操作；不存账号密码、身份证号或支付凭据。

大麦首版只打开验证过域名的官方网页、提示 App 操作、记录结果。没有自动刷新、排队操作、库存爬取、提交订单或支付。Android 只检测 USB 的 adb 连接及大麦 App 是否安装；不在未核对路径的情况下发送深链。别的平台作为规则资料及官方入口与机会记录，未验证能力显示为未接入。

选择器保持场次、人数、预算三项硬条件；仅对人工明确标为可买且价格能够判断的票档建议优先选择。未知、加载失败和售罄分别显示。新机会提醒只在软件运行时触发并记录去重；用户录入公告后可修改时区与来源。结果的待支付、已付款待出票、已出票由用户手动确认，不能推断成交。

检验以逻辑测试（时区、预算、选择、提醒及本地存储）和桌面界面实际操作为主。真实抢票概率在缺少可比数据前不作百分比承诺。
