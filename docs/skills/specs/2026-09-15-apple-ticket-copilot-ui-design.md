# 候票台 Apple 式购票助手 UI 重构设计

## 目标

把候票台从多页面管理工具收敛为一条清晰的购票路径：**搜索活动 → 选择场次 → 选择票档 → 选择人数 → 准备购票 → 在官方平台完成交易**。第一次使用者无需理解销售机会、平台能力或任务模型，也能完成一项购票准备。

本次只重构信息架构、视觉系统与交互表达，保留当前本地数据库、官方网页容器、Android ADB 连接和平台规则能力。应用不得把“打开官方入口”描述为自动下单或抢票成功。

## 参考结论

- [Mobbin](https://mobbin.com/mcp)、[Refero](https://refero.design/apps) 和 [Page Flows](https://pageflows.com/screens/desktop/saas/) 用于提炼真实产品的搜索、选择、确认、等待和结果流程。
- [SaaSFrame](https://www.saasframe.io/) 用于任务列表、设置和空状态的信息组织。
- [Land-book](https://land-book.com/design/website/saas) 与 [Lapa Ninja](https://www.lapa.ninja/category/saas/) 只用于排版、留白和品牌表达，不把营销页的大标题、复杂动画或装饰性卡片移入购票工作区。
- Apple 风格在本项目中表示：单屏一个主要动作、系统字体、清楚的层级、渐进展示、克制的阴影与模糊、可预测的导航和完整的键盘焦点；不复制任何产品界面。

## 信息架构

主导航由五项缩为三项：

1. **找票**：默认首页，承担搜索、官方网页浏览和活动信息读取。
2. **任务**：合并原“我的任务”和“销售日历”。默认显示按下一步时间排序的任务列表，可切换“全部 / 即将开始 / 待处理 / 已结束”，并在列表内显示时间线信息。
3. **设置**：合并“设备与会话”“平台规则”“本地数据”和网页版说明。内容按“手机连接、官方会话、通知与数据、平台说明”分组。

顶部栏只保留当前页面名、全局通知入口和外观切换。本地保存说明移入设置及首次使用提示，不持续占用顶部空间。

## 核心流程

### 1. 找到活动

首页首屏只显示统一搜索框、最近任务和必要的空状态说明。用户可输入歌手、活动名或官方链接；默认搜索大麦，无需先选择平台。搜索框末端提供平台按钮，用户需要时再展开全部渠道。

官方网页始终在当前应用窗口内打开。网页顶部使用紧凑浏览栏，包含返回、前进、刷新、当前官方域名和“读取活动”操作。页面识别成功后，不弹出大型表单，而在网页右侧打开购票准备面板。

### 2. 准备购票

准备面板固定为三个用户决定：

1. 场次：从公开页面明确识别出的日期和时间中选择一个或多个。
2. 票档：选择一个或多个可接受票档，点击顺序就是优先顺序，价格直接显示在票档内。
3. 人数：使用系统选择器，默认 1 人，并遵守已识别的单笔限购。

平台、活动名、场馆、时区、币种、来源网址和核实时间自动保存。只有无法可靠确定且会影响提醒或价格含义的信息才显示为待核对项。高级资料放在“识别详情”折叠区，不进入主流程。

面板底部只保留一个主要操作“准备并打开官方购票”，另有低强调的“仅保存”。主要操作保存任务并保持或打开对应官方网页/App。实名观演人、登录、验证码、选座、订单与付款由官方平台完成。

### 3. 开售专注模式

任务进入已开始或临近开始状态时，详情页变为专注布局：

- 顶部显示活动名、所选场次和距离开始的倒计时。
- 中部优先显示内置官方网页；App 专属活动显示手机连接状态和打开官方 App 的操作。
- 右侧窄栏显示所选票档顺序、人数、准备缺口和订单状态。
- 不显示统计卡、教程、平台对照或装饰性信息。
- 页面加载失败、状态未知和售罄使用不同状态，避免把网络故障误判为无票。

## 任务页

任务页采用单列列表，不再同时堆叠大面积 Hero、统计条、行动卡和任务卡。第一行只显示最紧急的一个动作，例如“完成准备”“进入官方页面”或“处理待支付订单”。

每个任务行显示活动名、平台、场次摘要、下一次明确机会和当前状态。点击进入详情。销售日历改成任务页的“按时间查看”视图，共用同一数据源和筛选器。

无任务时只提供“搜索第一场演出”操作；不再引导用户手工创建包含大量字段的空任务。手工录入作为设置中的辅助入口保留，供无法识别的活动使用。

## 视觉系统

### 颜色

- 浅色背景：`#F5F5F7`，主要表面：`#FFFFFF`，主文字：`#1D1D1F`，次文字：`#6E6E73`。
- 主操作色：`#007AFF`；深色模式使用更明亮的系统蓝变体。
- 成功、警告、错误只用于真实状态，不用于装饰。
- 移除网格背景、青绿色大渐变、发光点、满屏英文 eyebrow 和多层彩色卡片。

### 排版与空间

- 使用系统字体栈，中文优先 Microsoft YaHei UI / PingFang SC，数字使用等宽数字特性。
- 采用 4px 基础间距，常用间距为 8、12、16、24、32px。
- 页面标题 28px，区块标题 20px，正文 15–16px，辅助信息不小于 13px。
- 圆角分级为 8px（控件）、12px（普通表面）、16px（浮层）；不让所有元素使用同一大圆角。
- 边框使用低对比 hairline；阴影只用于浮层和临时面板。

### 动效与反馈

- 常规过渡 180ms，面板进入 240ms；只动画 `opacity` 和 `transform`。
- 点击在 100ms 内给出状态反馈；异步读取超过 300ms 显示骨架或进行中状态。
- 支持 `prefers-reduced-motion`，焦点环清晰，所有主要操作可通过键盘完成。
- 触摸目标不小于 44×44px，正文颜色达到 WCAG AA 对比度。

## 组件边界

- `AppShell`：三项导航、顶部工具栏和全局状态。
- `DiscoverWorkspace`：搜索、平台选择、内置网页与读取状态。
- `PurchaseSetupPanel`：场次、票档、人数和唯一主操作。
- `TaskHub`：任务筛选、列表、时间视图和最紧急动作。
- `FocusMode`：开售倒计时、官方入口、选择摘要与状态记录。
- `SettingsPage`：手机连接、会话、通知、本地数据和平台说明。

组件继续使用现有 React、TypeScript、Electron 和 CSS，不引入新的 UI 框架或远程字体。现有 `EventRecord` 数据保持兼容；页面重构不得要求数据库迁移。

## 错误与边界状态

- 无法自动识别：保留当前官方网页，显示“重新读取”和简化手工补充入口。
- 识别结果不完整：仅要求核对会影响提醒或购买条件的字段，不显示空白高级表单。
- 登录后页面不可访问：显示原始错误和“在系统浏览器打开”，保留当前任务与选择。
- 手机未连接、未授权或不支持：分别展示诊断步骤，不把“已安装 ADB”显示为“设备已就绪”。
- 官方网页状态未知：保持未知，不推断库存、排位或售罄。
- 已生成有效订单：主要操作切换为“处理订单”，停止引导重复提交。

## 验收标准

- 新用户启动后，一个主要动作即可开始搜索。
- 从已识别活动到打开官方入口，主路径只需要选择场次、票档和人数。
- 首页不要求先选平台；常用和全部平台仍可访问。
- 主导航只有“找票、任务、设置”。原销售日历、平台规则和设备功能都能在新结构中找到。
- 内置官方网页保持在当前窗口，活动识别成功后使用侧边准备面板，不弹出全屏资料表单。
- 任务页首屏最多显示一个主要行动区，不重复展示同一任务信息。
- 1024×768、1440×900 和窄窗口下无横向溢出；侧栏在窄窗口变为底部导航。
- 浅色、深色、键盘焦点、减少动态效果均通过 UI 回归测试。
- 现有任务可读取、编辑和打开；备份导入导出、ADB 状态及网页回退路径保持可用。
- 文案不声称自动下单、保证成功率、实时库存或排队优势。

## 实施边界

本轮不新增未经授权的自动点击、验证码处理、账号密码保存、证件保存、支付信息保存或第三方交易接口。自动化只覆盖公开信息读取、本地选择保存、提醒准备和打开官方入口。
